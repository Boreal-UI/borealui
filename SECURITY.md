# Security Policy

## Supported versions

Security fixes are applied to the latest published Boreal UI release. Consumers should upgrade to the newest versions of the `@boreal-ui/*` packages before reporting an issue that may already be resolved.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

Use GitHub's private vulnerability reporting flow on the [Boreal UI security advisories page](https://github.com/DaveC6662/borealui/security/advisories/new). Include the affected package and version, impact, reproduction steps or a proof of concept, and any suggested remediation.

You should receive an acknowledgement within 3 business days and an initial assessment within 7 business days. We will coordinate disclosure and credit with you after a fix is available. Please allow a reasonable remediation period before public disclosure.

## Scope

Reports are especially helpful when they involve:

- published `@boreal-ui/*` packages or the setup CLI;
- cross-site scripting, unsafe URL handling, or injection;
- dependency or build-pipeline compromise;
- leaked credentials or release-integrity failures;
- accessibility behavior that creates a security or privacy impact.

General bugs, feature requests, and non-security accessibility issues should use the public issue tracker.
